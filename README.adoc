= ddot.it — IntelliJ IDEA support
:toc:

Authoring support for *https://ddot.it[ddot.it]*, a minimal text format for typed knowledge graphs. Each line is a triple — `subject ..predicate.. object` — written with double-dot separators.

For a detailed walkthrough of every feature, see the xref:user-guide.adoc[User Guide].

== What is ddot.it?

https://ddot.it[ddot.it] is a line-oriented graph notation built around two separators:

* `..` — typed link: `subject ..predicate.. object`
* `....` — simple (untyped) link: `subject .... object`

Continuations and metadata extend a triple without repeating the subject:

[source,ddot]
----
Project Eagle ..started in.. 2024
..doc site.. example.com/docbase/8dcjsid

John Doe ..leads.. Project Eagle ,, ..since.. 2025

Project Eagle .... Moonshot

Dirk Hagemann ..works at.. SAP ,,
..year.. 2010
..fictive.. yes
,,
----

Lines starting with `..` continue the previous subject. `,,` opens metadata; a closing `,,` ends a multi-line metadata block.

For the full format spec and the canonical event JSON shape, see the https://ddot.it/developer-guide.html#events[ddot.it Developer Guide → Events].

== What this plugin does

* *Syntax highlighting* for `.ddot` files (configurable colors under _Settings → Editor → Color Scheme → ddot.it_).
* *Smart completions* that understand triple slots:
* typing in the subject slot suggests known subjects;
* typing in the predicate slot suggests known predicates;
* typing in the object slot suggests known objects.
* Multi-word entities (e.g. `John Doe`) complete as a single unit.
* Suggestions are *prefix-matched* (case-insensitive), not fuzzy.
* Picking a subject auto-inserts `..` and surfaces predicates; picking a predicate auto-inserts `..` and surfaces objects.
* On a fresh line after a complete triple, suggestions auto-open with `..rel..`-form predicates.
* When the cursor sits right after `..`, predicates show as `..rel..` items whose range absorbs the existing `..` (no doubled dots on accept).
* *Canonical formatter* (Code → Reformat Code, ⌘⌥L / Ctrl+Alt+L) — every triple becomes self-contained, with balanced spacing:
* Continuation lines get their inherited subject: `..predicate.. object` → `subject ..predicate.. object`
* Typed link → `subject ..predicate.. object`
* Simple link → `subject .... object`
* Metadata → `,, content` inline, `,,` at end of line
* *Structure view* — AsciiDoc-style section headings (`= Title`, `== Title`, …) form a tree, shown in bold, with the subjects of each section nested underneath; available in the Structure tool window and the file structure popup (⌘F12 / Ctrl+F12).
* *Folding* — collapses a subject and its continuation lines.
* *Live templates* — type a prefix, press Tab:
* `ddot-typed` — typed link
* `ddot-link` — simple link
* `ddot-property` — typed link with metadata
* `ddot-continue` — continuation predicate
* `ddot-meta` — metadata pair
* *Cardinality checking* — lines that violate a bound on a relation (`rel ..range.. T ,, ..cardinality.. 1`, scoped by `rel ..domain.. D`, or the vocabulary's `min cardinality` / `max cardinality`) get a yellow warning whose tooltip links to where the bound is stated; Alt+Enter jumps there.
* *Letter-case check* — names that occur in the project in different letter case (`Project Eagle` / `project eagle`) get a yellow warning; Alt+Enter unifies the spelling project-wide.
* *Relations without a direction* — a relation placed under both `links to` and `is linked from` gets a yellow warning on every statement that places it.
* All warnings come from the core library (`it.ddot.core.lint.DdotAnalysis`); `ddot lint` prints the same ones.
* *Rename* (Shift+F6) — renames an entity across the whole project, in every role, including embedded blocks in Markdown and AsciiDoc; names that differ only in letter case are listed but only renamed when you check them. *Find Usages* (Alt+F7) uses the same search.
* *Entity popup* — hover a subject, relation or object (or press Ctrl+Q) to see its relations and inverse relations across the whole project; click any item to jump to where that triple is stated.
* *Tools menu* (Tools → ddot.it):
* *Format Document* — same as Reformat Code;
* *Export as JSON* — emits one https://ddot.it/developer-guide.html#events[triple event] per line (JSONL) with fields `from`, `type`, `to`, `meta`, `kind`, `source`, `location`.

== Previews

ddot.it blocks render with the same role-aware coloring (subject / predicate / object / metadata / command) used in the editor — both inside Markdown and inside AsciiDoc, in IntelliJ's preview panes.

=== Markdown — zero setup

Open a `.md` file and use a fenced code block. The bundled JetBrains Markdown plugin is enough; no extra steps.

[source,markdown]
----
```ddot
Project Eagle ..started in.. 2024
..doc site.. example.com/docbase/8dcjsid

John Doe ..leads.. Project Eagle ,, ..since.. 2025
```
----

Recognised fence labels: `ddot`, `ddot.it`, `ddotit`. Colors come from your active editor color scheme — tweak them under _Settings → Editor → Color Scheme → ddot.it_; the preview tracks the change.

=== AsciiDoc

The https://plugins.jetbrains.com/plugin/7391-asciidoc[AsciiDoc plugin] doesn't expose an extension point for third-party preview renderers, and only loads Asciidoctor extensions from `<projectRoot>/.asciidoctor/lib/`. So the preview ships as an Asciidoctor extension that has to live next to your project — but you don't have to put it there yourself:

. Install the AsciiDoc plugin if you haven't already, and open your project.
. Open any `.adoc` file that contains a ddot block. The plugin drops `ddot-render.rb`, `ddot.rb` and `ddot-extension.rb` into `<projectRoot>/.asciidoctor/lib/` and tells you it did.
 `ddot.rb` is the https://github.com/Calpano/ddot.it-syntax-tools[ddot.it-syntax-tools] Rouge lexer, bundled at build time, and highlights `[source,ddot]` blocks in documents that set `:source-highlighter: rouge`.
. The AsciiDoc plugin shows a banner asking to trust the new extension files. Click *Enable* for all three.
. Open or refresh the AsciiDoc preview.

Nothing is written into projects that have no ddot blocks, and a plugin upgrade refreshes the installed copies on the next open. *Tools → ddot.it → Install AsciiDoc Preview Extension* does the same thing on demand — use it to repair a deleted or hand-edited copy, or to install before writing your first ddot block. To turn the automatic install off, set `ddot.asciidoc.autoinstall` to `false` in _Help → Find Action → Registry_.

After that, `[ddot]` / `[source,ddot]` listing blocks render with role coloring:

[source,adoc]
----
[source,ddot]
----
Project Eagle ..started in.. 2024

Dirk Hagemann ..works at.. SAP ,,
..year.. 2010
..fictive.. yes
,,
----
----

Recognised block labels: `ddot`, `ddot.it`, `ddotit`. The editor pane (syntax highlighting, completion, formatting on the block body) works without the install — only the AsciiDoc _preview rendering_ needs it.

Override the palette per document via AsciiDoc attributes (the Markdown side reads from the editor scheme directly and doesn't need this):

[source,adoc]
----
:ddot-color-subject: #aa00aa
:ddot-color-predicate: #1750eb
:ddot-color-object: #067d17
----

== Building from source

[source,bash]
----
mvn package
----

The plugin zip is at `target/ddotit-intellij-<version>.zip`. Install it via _Settings → Plugins → ⚙ → Install Plugin from Disk…_ and pick the zip.

Then open or create a `.ddot` file to try it.
